<objective>
Build the core Rust CLI and streaming engine for FastChunk. The engine packages files or recursive directories of arbitrary size, calculates cryptographic checksums on the fly, slices the stream into exact byte-limited chunk files (`data.part001`, `data.part002`, ...), and generates a structured `manifest.json`.

Purpose: Enable users to partition massive datasets (e.g. 40GB+) across capacity-constrained physical media (e.g. 15GB pen drives) with zero intermediate temporary disk files and rapid disk-speed streaming.
Output: Fully operational `fastchunk` executable, modular library (`fastchunk`), and comprehensive integration test suite.
</objective>

    - Define struct `PartInfo` deriving `Debug`, `Clone`, `serde::Serialize`, `serde::Deserialize`, `PartialEq`, `Eq`:
      - `pub filename: String`
      - `pub size: u64`
      - `pub sha256: String`
    - Define struct `ChunkedWriter`:
      - `out_dir: PathBuf`
      - `base_name: String`
      - `chunk_size: u64`
      - `current_part_idx: usize`
      - `current_chunk_written: u64`
      - `current_hasher: sha2::Sha256`
      - `current_file: Option<std::fs::File>`
      - `completed_parts: Vec<PartInfo>`
    - Implement `pub fn new(out_dir: impl AsRef<Path>, base_name: &str, chunk_size: u64) -> std::io::Result<Self>`:
      - Create `out_dir` if it does not exist.
      - Open first part file via helper `open_next_part()`.
    - Implement `fn open_next_part(&mut self) -> std::io::Result<()>`:
      - Format filename as `{base_name}.part{:03}` (format dynamically with 3 or more digits).
      - Create file in `out_dir`, assign to `current_file`, reset `current_chunk_written = 0`, reset `current_hasher = Sha256::new()`.
    - Implement `fn close_current_part(&mut self) -> std::io::Result<()>`:
      - Flush `current_file`.
      - Finalize `current_hasher`, hex-encode digest via `hex::encode`.
      - Append `PartInfo` to `completed_parts`.
      - Increment `current_part_idx`.
    - Implement `impl std::io::Write for ChunkedWriter`:
      - In a loop while input buffer is not empty:
        - Compute `remaining_in_chunk = chunk_size.saturating_sub(current_chunk_written)`.
        - If `remaining_in_chunk == 0`, close current part and open next part.
        - Slice input buffer by `std::cmp::min(buf.len() as u64, remaining_in_chunk)`.
        - Write slice to `current_file`, feed slice to `current_hasher.update(slice)`, add slice length to `current_chunk_written`.
        - Advance buffer slice.
      - Return original buffer length.
    - Implement `flush(&mut self)` to flush active file.
    - Implement `pub fn finish(mut self) -> std::io::Result<Vec<PartInfo>>`:
      - Close current part only if bytes were written to it or if it is part 1 (for empty streams).
      - Return `completed_parts`.
    - Add unit tests in `src/chunker.rs`:
      - Test multi-part splitting across exact byte boundaries (e.g. 1000 bytes with chunk_size 400 yields 400 + 400 + 200).
      - Test that writes which are exact multiples of chunk size do not create an empty trailing part file.
      - Test that SHA-256 hashes generated in `PartInfo` match standalone `sha2::Sha256` digest of written part files.
  </action>
  <acceptance_criteria>
    - `ChunkedWriter` slices stream at exact byte limit without exceeding `chunk_size`.
    - Writing exact multiples of `chunk_size` produces N parts, not N+1 parts.
    - SHA-256 hashes in `completed_parts` match the file contents on disk.
    - Unit tests in `src/chunker.rs` pass.
  </acceptance_criteria>

      - Setup the pipeline based on `mode`:

          - Create `tar::Builder::new(writer)`.

          - Finalize: `let parts = chunked_writer.finish()?;`
        - When `CompressionMode::Fast`:
          - Create `encoder = zstd::stream::write::Encoder::new(writer, 1)?`.

          - Append entries as above.
          - Unwrap pipeline in strict order:
            - `let encoder = builder.into_inner()?;`
            - `let chunked_writer = encoder.finish()?;`
            - `let parts = chunked_writer.finish()?;`
      - Return `PackagingResult { total_uncompressed_bytes, total_entries, parts }`.

| User CLI Input -> Engine | Untrusted source path, output directory path, and chunk size strings |
| Stream Slicing -> Filesystem | Output chunks and manifest written to target filesystem |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | Output Part Files | High | Mitigate | Compute cryptographic SHA-256 checksums per part during streaming write; store digests in `manifest.json`. |
| T-01-02 | Denial of Service | Memory Exhaustion (Large Files) | High | Mitigate | Maintain strictly O(1) memory footprint: stream TAR entries and Zstd frames directly into `ChunkedWriter` using bounded 1MB I/O buffers. |
| T-01-03 | Elevation of Privilege | Path Traversal in Archive Names | Medium | Mitigate | Normalize relative paths when appending files to the TAR archive; avoid absolute path prefixes. |
| T-01-04 | Tampering | Zero-Byte Trailing Chunks | Low | Mitigate | Prevent opening trailing chunk file on exact boundary until subsequent bytes actually arrive. |
</threat_model>
