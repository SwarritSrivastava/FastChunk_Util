       - Conventional archives (7z, xz) take 30+ minutes and require software installed on destination machines.
       - FastChunk slices across file boundaries into exact part sizes, generates zero-dependency native restore scripts (`restore.sh`, `restore.bat`, `restore.ps1`), bundles the native binary, and reconstructs the data at disk speed (500MB/s – 1.5GB/s+) in seconds.
    3. **Step-by-Step Tutorial**: "How to Move a 40GB Folder with a 15GB Pen Drive":

       - **Step 2: The Pen Drive Shuttle**:
         - Shuttling `part_001.bin` + metadata + scripts + binary to USB drive.
         - Moving to target machine directory `~/project_chunks/`.
         - Clearing USB drive and repeating for `part_002.bin` and `part_003.bin`.
       - **Step 3: Instant Restoration on Target Machine**:
         - *Option A (Native Binary)*: `./fastchunk restore ~/project_chunks -o ~/restored_project`
         - *Option B (Linux/macOS Zero-Install)*: `cd ~/project_chunks && ./restore.sh ~/restored_project`
         - *Option C (Windows Zero-Install)*: `restore.bat C:\restored_project` or `powershell -ExecutionPolicy Bypass -File restore.ps1 -OutputDir C:\restored_project`
    4. **Safety & Missing-Part Alerts**:

    5. **CLI Command Reference**:
       - Table of commands (`split`, `restore`) with all flags (`-s`, `-o`, `-m`, `-b`, `-v`, `--skip-verify`).
       - Supported size units: `14G`, `14GB`, `4000MB`, `500M`, `1GiB`, `2TB`.
       - Compression modes: `fast` (multi-threaded Zstandard level 1) vs `store` (zero-overhead raw streaming).
    6. **Architecture & Performance**:
       - Streaming TAR chunker with zero intermediate file copies.
       - Memory footprint: constant < 64MB RAM via fixed 256KB streaming buffers.
